Technical architecture

AR Invoice Dashboard, rebuilt native to Microsoft Fabric

The dashboard now runs entirely inside Fabric — a Fabric App for the frontend and Fabric User Data Functions for the backend — querying the Lakehouse's SQL analytics endpoint directly. No App Service, no Static Web Apps, no separate server to patch or pay for.

System diagram

Every request and the deploy path, in one picture — zones, identities, and what each arrow actually carries.

Two data-access paths

Picked per query, not per page — based on what the aggregation actually needs.

Lakehouse connector

Small, low-cardinality lookups

Native GraphQL connector straight to the Lakehouse. Used only for filter dropdown options — entities, invoice types, transaction classes.

  • Zero code — declarative entity mapping
  • Hard cap: ~100 groups per aggregated query
  • Fine for dimension tables, wrong for the fact table
SQL functions

Everything that aggregates real volume

Parameterized T-SQL run from a Rayfin User Data Function, against the ~1.3M-row FIN_AR_INVOICE_LINE_F fact table.

  • KPIs, trends, top customers, concentration
  • Economics, exceptions, insights, the full invoice table
  • No row cap — the database does the aggregating
△

Why two paths, not one: the connector's aggregation silently caps grouped results around 100 rows — undocumented, and only visible once invoice counts came back wrong at real scale. Anything touching the full fact table now goes through SQL functions instead.

Filtering

One shared filter state, pushed into every query as SQL parameters.

Entity, Invoice Type, Transaction Class, Year and Month live in one React state object at the top of the app. Every KPI, chart and the invoice table receives it and turns it into a parameterized WHERE clause server-side. Three charts (Invoice Type, Top Customers, Invoice Source) and both trend charts also write back into that same state on click — so clicking a bar filters everything else on the page, and clicking it again clears it.

Deploy

One command builds and ships both the app and the functions together.

1npx rayfin upbuilds frontend + functions, deploys both
2app identityfunctions run as the Fabric App's own owner — no manual tokens
3item owner onlySQL-connected functions can only be deployed by the app's actual owner
